API dokumentacija

Pregled endpointov, ki jih uporablja testna stran /ui/index.html, in kako si sledijo od klika na gumb do prikaza ZOI/EOR.

← nazaj na testno stran

Potek delovanja

  1. Uporabnik izpolni podatke dummy računa in klikne "Pošlji račun preko Event Mesh".
  2. Stran pokliče POST /ui/api/emit, ki objavi sporočilo na topic invoice/created v SAP Event Mesh.
  3. CAP aplikacija (subscriber.js) sporočilo prejme in sproži fiscalization-service.js.
  4. Servis pokliče FURS, prejme ZOI in EOR ter ju shrani v SAP HANA Cloud.
  5. Stran medtem vsakih 1,2 s poizveduje GET /ui/api/status/:invoiceId, dokler status ni CONFIRMED ali ERROR.
  6. Ko je status znan, stran izpiše ZOI, EOR in status v berljivi obliki.

Endpointi

GET /ui/index.html

Postreže glavno testno stran (statična datoteka, brez logike na strežniku).

POST /ui/api/emit

Objavi testni dogodek na SAP Event Mesh, topic invoice/created. Ne čaka na rezultat fiskalizacije — samo potrdi, da je bilo sporočilo oddano.

Request body (application/json)
{
  "invoiceId": "482913",
  "taxNumber": "10698655",
  "amount": 250.75,
  "premiseId": "POS1",
  "deviceId": "DEV1",
  "timestamp": "2026-09-10T09:15:00.000Z"
}
Response 202
{ "ok": true }
Response 500
{ "ok": false, "error": "..." }
GET /ui/api/status/:invoiceId

Prebere trenutni status računa neposredno preko akcije status na fisc.FiscalizationService. Kliče se ponavljajoče (polling), dokler fiskalizacija ni zaključena.

Path parametri
invoiceIdstringID računa, poslan v /ui/api/emit
Response 200 — v obdelavi
{ "Status": "PENDING", "ZOI": "6557229d...", "EOR": null }
Response 200 — zaključeno
{
  "Status": "CONFIRMED",
  "ZOI": "6557229d3af1a54ddbe79074e8478ec6",
  "EOR": "99996046-8c65-41dc-9403-f6c3def4384d"
}
